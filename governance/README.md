# Eldgrim — Governance Rulebook

**Status:** Working framework, not a ratified constitution.  
**Source baseline:** Consolidated guild rules and governance framework, 10 November 2026, v0.1.  
**Scope:** Public rules for Eldgrim's intended stewardship of Amberhearth on World of Warcraft Forever (Alliance Roleplay).

Eldgrim's administrative authority is an approved design goal. This directory records confirmed decisions, proposals, operational boundaries, and unanswered questions separately so every chapter can be refined without silently creating new policy.

**Repository boundary:** This is Eldgrim's *working governance framework*. The fellowship's binding charter and guild operations belong in [ROARguild](https://github.com/babunidev/ROARguild). Changes here do not amend that charter or enable AI-controlled administration automatically. Private character canon, live member information, credentials, and runtime data are excluded from this public repository.

## Editing and approval rules

1. Work in the relevant numbered chapter; preserve section-specific unresolved questions in its **Refinement queue**.
2. Label new policy as **Established**, **Developing**, **Proposed**, **Open**, or **Retired** using [documentation standards](../docs/DOCUMENTATION.md).
3. A draft, proposal, unanswered question, or example is **not** an enforceable rule. Confirm approval with the creative and record meaningful decisions in [DECISIONS.md](../docs/DECISIONS.md).
4. Reconcile changes with the [ROARguild charter](https://github.com/babunidev/ROARguild/blob/main/guild/CHARTER.md) before treating guild-wide policy as adopted. Do not silently override a guild charter from this repository.
5. Preserve technical boundaries from [agent security](../agent/SECURITY.md), [agent memory](../agent/MEMORY.md), and [bot direction](../bot/README.md). Implementation and integration evidence must be tracked separately.
6. Keep concealed character canon and real-world member information outside this public repository.

## Current implementation boundary

The daily Ollama agent, AI-driven administration, and **founder-PC-local interpreted-memory database** are not yet implemented or verified. The live bot's separate registration and administrative data remains on the server (Q138). The proposed hierarchy in Chapter 15 has not been ratified. Q161–170 establish **how** a charter may become binding and require a verified safeguard-and-founder-approval gate before activating new autonomous administration; no charter ratification or deployment approval occurred.
